# Building the local (LAN) Android app

A separate APK, **GeoAttend (Local)**, that talks to the server running on
this PC over the Wi-Fi instead of the Render deployment. Use it when Render is
down or suspended, or for testing. It is built on this PC with Gradle, so it
doesn't use up EAS build credits.

## How it works
- `mobile/app.config.js` wraps `mobile/app.json`. When the `API_BASE_URL`
  environment variable is set, it points the app at that address, renames it
  to "GeoAttend (Local)", and allows plain `http://` (Android release builds
  refuse `http://` otherwise). Without `API_BASE_URL` the config is exactly
  `app.json`, so normal EAS preview/production builds still use Render.
- `expo-build-properties` (in `mobile/package.json`) is what allows `http://`.
- `mobile/android/` is generated by `expo prebuild` and is gitignored.
- The finished APK is copied to `public/downloads/` (also gitignored) so a
  phone can download it straight from the server.

## Requirements (already on this PC)
- Android SDK at `%LOCALAPPDATA%\Android\Sdk`
- JDK 21 at `C:\Program Files\Android\openjdk\jdk-21.0.8` (comes with Android
  Studio). The system default Java 22 is too new for Expo SDK 51.
- The phone and the PC on the **same Wi-Fi**, and the server running
  (`npm run dev`). Windows Firewall must allow Node.js on the network (it
  already does).

## Step 1. Find the PC's LAN IP
```powershell
ipconfig
```
Under **Wireless LAN adapter Wi-Fi**, copy the **IPv4 Address**
(e.g. `192.168.254.107`). Check it from the phone's browser:
`http://<IP>:3000/api/` should show
`{"success":false,"message":"Route not found: GET /api/"}`. That JSON means
the phone can reach the server.

## Step 2. Generate the Android project (first time only)
Only needed once, or again after changing `app.json` / `app.config.js` or
adding a package with native code.
```powershell
cd C:\geoattend-pro\mobile
npx expo install expo-build-properties   # first time only
$env:API_BASE_URL = 'http://192.168.254.107:3000/api'
$env:CI = '1'
npx expo prebuild -p android --no-install
```

## Step 3. Build the APK
Repeat this after every change to the app's code, or when the IP changes.
Put the IP from Step 1 on the `API_BASE_URL` line.
```powershell
$env:JAVA_HOME    = 'C:\Program Files\Android\openjdk\jdk-21.0.8'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:API_BASE_URL = 'http://192.168.254.107:3000/api'
$env:NODE_ENV     = 'production'
cd C:\geoattend-pro\mobile\android
.\gradlew.bat assembleRelease --no-daemon --project-cache-dir C:\gcache
```
Wait for `BUILD SUCCESSFUL`. The first build takes about 40 minutes; later
ones take 2–3 minutes. `--project-cache-dir C:\gcache` avoids a Windows
Gradle error ("Could not move temporary workspace").

## Step 4. Publish the APK for download
```powershell
Copy-Item C:\geoattend-pro\mobile\android\app\build\outputs\apk\release\app-release.apk C:\geoattend-pro\public\downloads\GeoAttend-Local.apk -Force
```

## Step 5. Install it on the phone
1. On the phone's browser, open
   `http://<IP>:3000/downloads/GeoAttend-Local.apk` and download it.
2. Open the file and allow "Install unknown apps" if asked.
3. **First install only:** uninstall the EAS-built GeoAttend first. The local
   build is signed with a different key, so Android won't install it over the
   old one. The phone will also count as a new device, so approve it again in
   **Device Management**. Later local builds install over the previous one.

## When the PC's IP changes
The server address is built into the APK, so a new IP means a rebuild:
1. `ipconfig` to get the new IPv4 address (Step 1).
2. Run Step 3 with the new IP on the `API_BASE_URL` line. No need to repeat
   Step 2.
3. Run Step 4.
4. On the phone, download from `http://<new IP>:3000/downloads/GeoAttend-Local.apk`
   and install it over the old one. No uninstall, no new device approval.

The **Office Network (Allowed IPs)** list in Settings is not affected: it
checks the internet line's public IP, not the PC's LAN IP.

To stop the IP from changing, reserve it for this PC in the router's DHCP
settings (router admin page, usually `192.168.254.254` or `192.168.1.1`).

## Notes
- `mobile/eas.json` also has a `local` profile for when EAS builds are
  available again (`eas build -p android --profile local`). The Gradle build
  above does **not** read `eas.json`; only the `API_BASE_URL` in Step 3 counts.
- Position and Classification lists in the app come from the server (managed
  from the dashboard's employee form), so changing them doesn't need a new APK.
